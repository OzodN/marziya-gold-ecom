# Project AI Control Plane (`.ai/`)

## Назначение
Директория `.ai/` представляет собой **контрольный слой координации AI-агентов** для проекта `marziya-gold_ecom`. Она не содержит прикладного кода самого приложения, а обеспечивает правила, контракты, контекст, регламенты передачи задач и защиту от конфликтов при параллельной разработке.

---

## Структура контрольного слоя

```
.ai/
├── README.md                  # Данное описание
├── instructions/              # Общепроектные инструкции для агентов
│   ├── source-of-truth.md     # Модель источников истины и иерархия авторитетности
│   ├── context-loading.md     # Обязательный регламент загрузки контекста
│   └── handoff-protocol.md    # Формат и правила передачи задач (handoff)
├── context/                   # Лаконичный агентский контекст предметной области
│   ├── project.md             # Общее описание проекта и стек
│   ├── domain.md              # Сущности (Product, Selection, Inquiry, Stone)
│   ├── terminology.md         # Обязательный словарь терминов UI ("Моя подборка")
│   ├── constraints.md         # Технические ограничения и Zero-Maintenance
│   ├── non-goals.md           # Запрещенная функциональность (нет цен/оплаты/склада)
│   └── integrations.md        # Внешние сервисы (Cloudinary, Telegram, PaaS)
├── stack/                     # Стек инструментов и навыков
│   └── aas-stack.json         # Манифест привязки глобальных навыков к ролям
├── agents/                    # Профили ролей проектных субагентов
│   ├── orchestrator.yaml      # Ведущий архитектор-координатор
│   ├── backend.yaml           # Инженер Spring Boot 4.1.1 / Java 21
│   ├── frontend.yaml          # Инженер Next.js 15+ / React 19 / shadcn/ui
│   ├── database.yaml          # Архитектор PostgreSQL / Flyway
│   ├── qa.yaml                # Инженер тестирования (JUnit 5, Playwright)
│   ├── security.yaml          # Специалист по безопасности (Spring Security, JWT)
│   ├── devops.yaml            # Инженер инфраструктуры и CI/CD
│   └── reviewer.yaml          # Код-ревьюер и шлюз контроля качества
├── orchestration/             # Контракты оркестрации и параллелизма
│   ├── ownership.yaml         # Матрица владения файлами и директориями
│   ├── capabilities.yaml      # Права на запуск субагентов и делегирование
│   ├── concurrency.yaml       # Правила параллельной работы через Git Worktrees
│   ├── routing.yaml           # Маршрутизация задач по путям и тегам
│   └── gates.yaml             # Обязательные шлюзы контроля перед мержем
├── workflows/                 # Регламенты стандартных сценариев
│   ├── feature.md             # Разработка фичи
│   ├── bugfix.md              # Исправление ошибки
│   ├── architecture-change.md # Архитектурные изменения и выпуск ADR
│   ├── database-change.md     # Изменение схемы БД через Flyway
│   ├── security-review.md     # Аудит безопасности
│   └── release.md             # Подготовка релиза
├── work/                      # Дюрабельная система задач
│   ├── registry.yaml          # Единый реестр задач и их статусов
│   ├── active/                # Символические ссылки на активные задачи
│   ├── tasks/                 # Директории задач (TASK-XXXX/task.yaml, plan.md)
│   └── handoffs/              # Шаблоны и архив хендоффов
├── decisions/                 # Указатели на принятые ADR
├── state/                     # Состояние системы
│   └── generated/             # Сгенерированные графы и срезы (НЕ источник истины)
└── reports/                   # Аналитические отчеты и результаты аудитов
    └── agent-discovery.md     # Отчет об исследовании среды Antigravity
```
