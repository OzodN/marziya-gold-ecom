# Руководство AI-Native инженера по эксплуатации системы (Operator Guide)

## 1. Ментальная модель: Кто такой AI-Native инженер в этой системе?
В этой архитектуре вы больше не занимаетесь ручным набором кода (`apps/backend` или `apps/frontend`).
Ваша роль — **Lead Architect, Dispatcher & Quality Gatekeeper**.

Вы управляете проектом через:
1. **Декларативные манифесты** (`.ai/work/registry.yaml`, `task.yaml`).
2. **Контракты** (`docs/api/openapi.yaml`, `ownership.yaml`).
3. **Шлюзы качества** (`gates.yaml`, `scripts/validate-ai-state.ps1`).

---

## 2. Стандартный рабочий цикл (Day-to-Day Lifecycle)

### Шаг 1: Создание / выбор задачи
1. Откройте `.ai/work/registry.yaml`.
2. Выберите задачу в статусе `ready` (например, `TASK-0002`) или добавьте новую.
3. Проверьте зависимости: если задача зависит от другой, зависимость должна иметь статус `done`.

### Шаг 2: Постановка задачи агенту
Вы отправляете агенту директивный промпт со ссылкой на идентификатор задачи.
> **Пример промпта:**
> *"Ты выступаешь в роли `database` агента. Твоя задача — выполнить `TASK-0002` согласно `.ai/work/tasks/TASK-0002/task.yaml` и регламенту `.ai/workflows/database-change.md`. Создай отдельный Git worktree и начни реализацию."*

### Шаг 3: Изолированное выполнение (Git Worktree)
Агент (или вы) запускает создание ворктри:
```bash
git worktree add .worktrees/TASK-0002-initial-schema -b feat/TASK-0002-initial-schema
```
Агент работает исключительно внутри `.worktrees/TASK-0002-initial-schema` и правит только разрешенные в `ownership.yaml` файлы.

### Шаг 4: Приемка и проверка артефактов (Handoff)
По завершении работы агент обязан:
1. Запустить локальные тесты / компиляцию.
2. Создать `.ai/work/tasks/TASK-0002/handoff.md`.
3. Закоммитить код в свою ветку по стандарту Conventional Commits.
4. Перевести статус задачи в `review`.

### Шаг 5: Запуск валидации репозитория
Вы (или агент-ревьюер) запускаете скрипт проверки целостности:
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\validate-ai-state.ps1
# Или в Linux/Mac/CI:
./scripts/validate-ai-state.sh
```

### Шаг 6: Интеграция в `main` и очистка
1. Слияние ветки в `main`:
   ```bash
   git merge --ff-only feat/TASK-0002-initial-schema
   ```
2. Удаление ворктри:
   ```bash
   git worktree remove .worktrees/TASK-0002-initial-schema
   git branch -d feat/TASK-0002-initial-schema
   ```
3. Обновление статуса в `.ai/work/registry.yaml` и `task.yaml` на `done`.
4. Автоматическое снятие блокировки с зависимых задач (например, `TASK-0003` переходит в `ready`).

## 3. Сценарий: Сброс или переключение сессии (Cold Start / Memory Reset)

### В чем проблема?
У LLM контекстное окно ограничено. Если диалог стал слишком длинным, память сжимается (compaction) или вы открываете абсолютно новый чат/терминал, агент "забывает", что происходило ранее.

### Как система решает это:
**Вся память системы дюрабельна и хранится в файлах, а не в оперативной памяти чата.**

### Ваши действия при открытии новой сессии:
Просто отправьте агенту вводный промпт "холодного старта":
> **Промпт холодного старта:**
> *"Начинаем новую сессию. Загрузи контекст согласно `.ai/instructions/context-loading.md`. Проверь `.ai/work/registry.yaml`, найди активную задачу и доложи статус."*

Агент выполнит:
1. Чтение `AGENTS.md` (подхватит все запреты и правила).
2. Чтение `.ai/context/project.md` и терминологии.
3. Чтение `registry.yaml` и `task.yaml` текущей задачи.
4. Чтение последнего `handoff.md`.
**Результат:** Через 5 секунд агент имеет 100% восстановленный контекст без единой потери информации.

## 4. Сценарий: Смена инструмента или агента (Antigravity -> Claude Code / Cursor / Codex)

### В чем проблема?
Сегодня вы используете Antigravity CLI. Завтра проект открывает коллега в **Claude Code**, через неделю вы подключаете **Cursor IDE** или запускаете агента на базе OpenAI / DeepSeek.

### Почему эта система абсолютно переносима (Tool-Agnostic):
1. **Стандарт `AGENTS.md`:** Является общепринятым стандартом директив для AI-агентов (поддерживается Antigravity, Claude Code, Cursor, OpenCode, Aider).
2. **Отсутствие проприетарного бинарного состояния:** Все манифесты написаны на человеко- и машиночитаемых `YAML` и `Markdown`.
3. **Стандартные индустриальные протоколы:**
   - Спецификация API — **OpenAPI 3.1** (понимают абсолютно все LLM).
   - Схема базы — **Flyway SQL** (нативный SQL).
   - Ветвление — нативный **Git Worktrees**.
4. **Кроссплатформенная валидация:** Скрипты проверки дублируются на `PowerShell` (Windows) и `Bash` (Linux/macOS/CI).

### Ваши действия при переходе на Claude Code:
1. Запустите в корне репозитория:
   ```bash
   claude
   ```
2. Claude Code автоматически прочитает корневой `AGENTS.md`.
3. Дайте команду:
   > *"Мы ведем разработку по регламентам в `.ai/`. Ознакомься с `.ai/instructions/operator-guide.md` и возьми в работу задачу TASK-0002 в изолированном ворктри."*
4. Claude Code выполнит задачу в точности по тем же правилам, заполнит тот же `handoff.md` и не нарушит архитектуру.

## 5. Сценарий: Параллельная работа нескольких агентов одновременно

Если вам нужно разрабатывать бэкенд и фронтенд одновременно:
1. **Терминал 1 (Backend Agent):**
   ```bash
   git worktree add .worktrees/TASK-0003-backend -b feat/TASK-0003-backend
   ```
   Запускаете агента: он работает только в `apps/backend/` и ориентируется на `docs/api/openapi.yaml`.
2. **Терминал 2 (Frontend Agent):**
   ```bash
   git worktree add .worktrees/TASK-0004-frontend -b feat/TASK-0004-frontend
   ```
   Запускаете второго агента: он работает только в `apps/frontend/`, используя mock-данные или контракт `docs/api/openapi.yaml`.
3. **Результат:** Никаких конфликтов файлов (разные директории), никаких конфликтов Git (разные ветки и ворктри).

---

## 6. Чек-лист безопасности инженера (Чего НЕЛЬЗЯ делать)
1. **Никогда не разрешайте агенту коммитить напрямую в `main` без ворктри.**
2. **Никогда не меняйте API без обновления `docs/api/openapi.yaml`.** Если бэкенд добавит поле, которого нет в контракте, фронтенд сломается.
3. **Никогда не удаляйте `handoff.md`** — это дюрабельный след для аудита.
4. **Всегда запускайте `scripts/validate-ai-state.ps1` перед релизом.**
