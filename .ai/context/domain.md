# Доменная модель и бизнес-сущности

## 1. Изделие (Product)
- Все изделия изготавливаются **под заказ**.
- Изделие имеет категорию, артикул (SKU), название, slug, описание, статус видимости (`is_visible`), упорядоченные фотографии (`ProductImage`).
- **Динамические характеристики (`characteristics`)**: массив пар `name` и `value` в формате JSONB. Имя выбирается из глобального справочника (`CharacteristicKey`), значение — строка (String).
- **Камни (`ProductStone`)**: изделие содержит 0..N камней. Каждый камень связан с типом (`StoneType`) и хранит собственный набор характеристик в JSONB (вес в каратах, чистота, цвет, огранка и т.д.).

## 2. Подборка клиента (Selection)
- Локальная клиентская коллекция выбранных изделий.
- Хранится в браузере (`localStorage`).
- Не имеет цены, расчета стоимости доставки и налогов.
- Содержит выбор желаемого количества для каждого изделия (`1..N`).
- При открытии проходит "тихую валидацию" (silent validation): если товар скрыт/удален мастером, он отображается серым как архивный.

## 3. Заявка (Inquiry)
- Формируется клиентом из содержимого Подборки.
- Содержит: Имя клиента, Телефон, опциональный Комментарий.
- Позиции заявки (`InquiryItem`) содержат **полный неизменяемый JSON-снапшот** (`product_snapshot`): артикул, название, ссылку на фото, все характеристики и данные о камнях на момент заказа. Изменение каталога в будущем не влияет на заявку.
- Жизненный цикл статусов: `NEW` -> `CONTACTED` -> `IN_PROGRESS` -> `COMPLETED` (или `REJECTED`).
- Изменение статуса требует **явного сохранения по кнопке** администратора и фиксируется в `InquiryStatusHistory`.
