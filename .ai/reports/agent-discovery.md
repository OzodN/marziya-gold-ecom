## 2. Что обнаружено в глобальной среде

### 2.1. Механизмы и среда выполнения субагентов (Antigravity Runtime)
1. **Встроенные типы субагентов:**
   - `self`: Наследует полную конфигурацию родительского агента, включая инструменты, системный промпт и модель. Подходит для делегирования задач с полным доступом к записи и командам в изолированном контексте.
   - `research`: Субагент только для чтения (read-only tools), предназначенный для исследования кодовой базы, поиска в интернете и сбора фактуры без загрязнения родительского контекста.
2. **Нативные API/инструменты управления субагентами:**
   - `invoke_subagent`: Параллельный/фоновый выпуск субагентов. Поддерживает режимы рабочего пространства (`Workspace`: `inherit`, `branch`, `share`) и выбор модели (`inherit`, `flash_lite`, `flash`, `pro`).
   - `define_subagent`: Динамическая регистрация новых специализированных типов агентов на время сессии с заданием системного промпта, прав на запись (`enable_write_tools`) и вызова MCP (`enable_mcp_tools`).
   - `manage_subagents`: Управление жизненным циклом (`list`, `status`, `kill`, `kill_all`).
   - `send_message`: Межагентная шина передачи сообщений по `conversationId`.
   - `schedule`: Таймеры и cron-планировщик для отслеживания фоновых задач.

### 2.2. Правила и иерархия контекста (Hierarchical Rules)
- Механизм **`AGENTS.md` / `GEMINI.md`**: Автоматическое обнаружение правил при обходе файлового дерева от текущей директории до корня репозитория.
- Ограничение размера одного файла правил: **24 КБ (24 000 байт)**.
- Совокупный бюджет правил: **20 000 токенов**.
- Механизм прогрессивного раскрытия (progressive disclosure): подробное содержимое загружается по требованию, в контекст первично попадают метаданные.

## 3. Анализ готовности агентов и пробелы

### 3.1. Переиспользуемые глобальные механизмы
- Базовый рантайм `self` и `research`.
- Механизм `using-git-worktrees` для предотвращения конфликтов в рабочем дереве при параллельном исполнении.
- Нативная шина сообщений `send_message` + reactive wakeup (отсутствие поллинга со стороны ведущего агента).

### 3.2. Что отсутствует в глобальной среде (Missing Components)
- Нет предустановленных готовых статических демонов/субагентов узкого профиля (отдельного `BackendAgent`, `FrontendAgent`, `DatabaseAgent`, `SecurityAgent`, `DevOpsAgent`, `ReviewerAgent`).
- Нет предопределенных прав владения путями проекта (Code Ownership boundaries).
- Нет централизованной очереди/реестра задач с конечным автоматом состояний (`draft` -> `ready` -> `in_progress` -> `review` -> `qa` -> `done`).
- Нет машиночитаемого сопоставления проектных ролей и установленных глобальных навыков.

## 4. Архитектурное разделение: Глобальное vs Локальное

| Компонент | Уровень размещения | Обоснование |
|---|---|---|
| Исполняемые файлы навыков (`SKILL.md`) | **Глобальный** (`~/.gemini/antigravity-cli/skills/`) | Навыки уже установлены в ОС. Дублирование в проект запрещено правилами. |
| Среда выполнения субагентов | **Глобальный** (Antigravity engine) | Примитивы вызова (`invoke_subagent`, `define_subagent`) встроены в платформу. |
| Манифест стека навыков (`aas-stack.json`) | **Проектный** (`.ai/stack/`) | Фиксирует, какие именно глобальные навыки требуются для проекта. |
| Ролевые профили агентов (`.ai/agents/*.yaml`) | **Проектный** (`.ai/agents/`) | Описывают системные промпты, границы владения, разрешенные инструменты. |
| Матрица владения путями (`ownership.yaml`) | **Проектный** (`.ai/orchestration/`) | Изолирует зоны ответственности агентов для предотвращения перезаписи кода. |
| Матрица параллелизма (`concurrency.yaml`) | **Проектный** (`.ai/orchestration/`) | Регулирует, какие задачи могут выполняться одновременно через Git worktrees. |
| Реестр задач и артефакты (`.ai/work/`) | **Проектный** (`.ai/work/`) | Дюрабельное хранилище состояния задач и хендоффов между сессиями. |
| Иерархия правил `AGENTS.md` | **Проектный** (Корень и подмодули) | Контекстные правила для каждого слоя архитектуры. |

## 5. Выводы и стратегия реализации
1. **Оркестратор (Orchestrator):** Главный агент (координатор) запускается с профилем архитектора. Он создает задачи в `.ai/work/`, назначает исполнителей и инициирует субагентов через `invoke_subagent` с соответствующей ролью и привязкой к Git Worktree.
2. **Специалисты (Specialist Agents):** Создаются как проектные обертки над рантаймом `self` с жестко заданными границами владения файлами (ownership) и назначенными глобальными навыками.
3. **Безопасность параллельной разработки:** Ни один агент не работает в основном рабочем дереве одновременно с другими. Каждый субагент работает в ветке/ворктри `.worktrees/<branch>`, производит изменения строго в своей зоне владения и передает результат через структурированный `handoff.md`.
