## 1. Резюме аудита и итоговый вердикт (Executive Summary & Verdict)

### Итоговый вердикт: **CHANGES_REQUESTED**

Витрина ювелирной мастерской Marziya Gold демонстрирует исключительно высокий уровень визуальной культуры, безупречно передает атмосферу премиального камерного ателье и демонстрирует **100% соблюдение утвержденной терминологии** (полное отсутствие понятий «корзина», «купить», «checkout»).

Однако аудит выявил ряд критических недочетов в сфере **доступности (A11y)**, **мобильной эргономики (тач-таргеты)**, **обработки ошибок (Error state)** и **целостности навигационного сценария пользователя (User Journey)**, нарушающих канонические требования документа `docs/design/ux-criteria.md`.

### Сильные стороны (Key Highlights):
1. **Абсолютная терминологическая чистота:** В кодовой базе обеих задач (`TASK-0005`, `TASK-0009`) зафиксировано ровно **0** упоминаний слов «Корзина», «Cart», «Купить», «Оформить заказ», «Checkout». Везде единообразно применены термины «Моя подборка», «В подборку», «Отправить запрос», «Индивидуальный заказ».
2. **Премиальная эстетика Luxury Minimalist:** Глубокая благородная палитра (`noir-950`, `noir-900`, деликатные акценты `gold-400`/`gold-500`), классическая шрифтовая пара *Playfair Display* (Serif) и *Inter* (Sans), выверенный трекинг и воздух.
3. **Бесшовный скелетон без сдвига макета:** `ProductCardSkeleton.tsx` повторяет структуру реальной карточки 1-в-1, устраняя Cumulative Layout Shift (CLS).
4. **Мобильная шторка фильтров:** `CatalogFilters.tsx` образцово реализует мобильный Bottom Sheet Drawer с pull-ручкой, блокировкой скролла body и плавным выездом снизу.

### Критические блокирующие замечания (Blockers & Majors):
1. **`InquiryModal.tsx` (Blocker):** Модальное окно не закрывается по клавише `Escape` и по клику на оверлей/бэкдроп. Отсутствуют обязательные атрибуты доступности `role="dialog"` и `aria-modal="true"`.
2. **`InquiryModal.tsx` (Major):** Ошибки валидации выводятся общим алерт-баннером сверху со скачком макета вместо локализованных подсказок под полями ввода.
3. **Тач-таргеты < 44×44px (Major):** Кнопки управления количеством (`+`/`-`), удаление (`Trash2`), крестики закрытия диалогов и кнопки пагинации имеют габариты от 22px до 36px, что нарушает стандарты Apple HIG / Android Material (п. 3.2 `ux-criteria.md`).
4. **`ProductCard.tsx` (Major):** Карточка товара в каталоге не имеет ссылок на детальную страницу `/product/[slug]`. Клик по фото или названию изделия не переводит на карточку.
5. **`CatalogView.tsx` (Major):** При сбое сетевого запроса к API компонент не отображает состояние ошибки (Error state с кнопкой «Повторить попытку»), а ошибочно показывает заглушку пустого каталога («Изделия не найдены»).
6. **`Header.tsx` (Minor/Major):** На экранах смартфонов (<640px) скрыты ссылки навигации без предоставления мобильного меню (пользователь не может перейти в «Каталог» из шапки).

### 2.2. Измерение 2: Матрица обязательных состояний (Component State Matrix)
*Критерий: Default, Hover/Focus, Loading (Content-aware Skeleton), Empty с CTA, Error с валидацией, Disabled.*

1. **Loading State (Загрузка):**
   - Реализован `ProductCardSkeleton.tsx` с идеальной геометрией: пропорция изображения `aspect-square`, блок SKU, заголовок, две плашки характеристик и кнопка действия.
   - В `CatalogView.tsx` при `isLoading === true` рендерится сетка из 6 скелетонов.
   - В `app/catalog/page.tsx` и `app/catalog/[categorySlug]/page.tsx` внедрен React `Suspense` с резервным `CatalogLoadingFallback`.
   - Полноэкранные блокирующие спиннеры отсутствуют, верстка не прыгает. (**PASSED**)

2. **Empty State (Пустые состояния):**
   - **Подборка (`SelectionSheet.tsx`):** Иконка камня `Gem`, деликатный заголовок «Ваша подборка пуста», мотивирующий текст и явный CTA-баттон «Перейти к изделиям».
   - **Каталог (`CatalogView.tsx`):** Иконка `Gem`, понятное пояснение и кнопка «Сбросить все фильтры». (**PASSED**)

3. **Disabled State (Неактивные элементы):**
   - `Pagination.tsx`: стрелки "Назад"/"Вперед" получают `disabled:opacity-40 disabled:cursor-not-allowed`.
   - `InquiryModal.tsx`: кнопка отправки блокируется во время запроса (`disabled={isSubmitting}`) с анимацией `Loader2` и текстом «Отправка запроса...».
   - `SelectionSheet.tsx`: изделия, ставшие недоступными, получают `opacity-50 grayscale` и статус «Временно недоступно для запроса». (**PASSED**)

4. **Hover & Focus States:**
   - Элементы имеют плавные переходы `transition-all duration-200/300`.
   - ⚠️ **Замечание:** У кнопок пагинации, карточек товаров и чипсов фильтров отсутствует выраженный видимый клавиатурный индикатор фокуса (`focus-visible:ring-2 focus-visible:ring-gold-400`).

5. **Error State (Состояния ошибок) — ⚠️ ОБНАРУЖЕНЫ ДЕФЕКТЫ:**
   - ❌ **`InquiryModal.tsx`:** При незаполненных полях («Ваше имя», «Телефон») отображается общий баннер ошибки вверху формы:
     ```tsx
     {errorMessage && (
       <div className="mb-4 rounded-lg bg-red-950/50 border border-red-500/30 p-3 text-xs text-red-300">
         {errorMessage}
       </div>
     )}
     ```
     Это нарушает п. 2 `docs/design/ux-criteria.md`: подсказки валидации обязаны быть локализованными непосредственно под проблемными полями ввода («Пожалуйста, укажите ваше имя», «Укажите контактный номер телефона») с подсветкой границы поля (`border-red-500/80`) без скачков высоты модального окна.
   - ❌ **`CatalogView.tsx`:** В блоке загрузки данных:
     ```tsx
     catch (err) {
       console.error("Failed to load products", err);
     }
     ```
     При сбое сети или 500 ошибке бэкенда состояние ошибки в UI не сохраняется. Пользователю ошибочно демонстрируется состояние Empty («Изделия не найдены»). Требуется ввести состояние `error: string | null` и отображать плашку с сообщением о сбое соединения и кнопкой `[ Повторить попытку ]`.

**Оценка измерения: 6.5/10 (CHANGES_REQUESTED)**

### 2.3. Измерение 3: Mobile-First Эргономика (Mobile Ergonomics)
*Критерий: Touch Targets >= 44×44px, мобильные шторки Bottom Sheet, Thumb Zone на смартфонах от 375px.*

1. **Размер тач-таргетов (Touch Targets < 44×44px) — ❌ СИСТЕМНОЕ НАРУШЕНИЕ:**
   Регламент Apple HIG / Android Material и п. 3.2 `docs/design/ux-criteria.md` требуют кликабельную область не менее **44 × 44 CSS пикселей**:
   - `SelectionSheet.tsx`, строка 105: Кнопка закрытия `X` имеет класс `p-2` с иконкой `h-5 w-5` (итого 36×36px).
   - `SelectionSheet.tsx`, строка 171: Кнопка удаления `Trash2` имеет класс `p-1` с иконкой `h-3.5 w-3.5` (итого **22×22px**!). На смартфоне попасть пальцем по 22px крайне затруднительно.
   - `SelectionSheet.tsx`, строки 199, 210: Кнопки счетчика `Minus` и `Plus` имеют класс `p-1` с иконкой `h-3.5 w-3.5` (итого **22×22px**!). Вызывает случайные промахи при изменении количества.
   - `InquiryModal.tsx`, строка 79: Кнопка закрытия `X` — `p-2` (36×36px).
   - `CatalogSearch.tsx`, строка 62: Кнопка очистки поиска `X` — `p-1` (22×22px).
   - `Pagination.tsx`, строки 95, 121, 138: Все кнопки пагинации имеют фиксированные размеры `h-9 w-9` (36×36px) вместо минимальных 44×44px.
   - `ProductCard.tsx`, строка 93: Кнопка «В подборку» имеет паддинг `py-2.5` (высота кнопки около 36px, рекомендуется `min-h-[44px]`).

2. **Мобильные шторки (Bottom Sheets vs Side Drawers):**
   - `CatalogFilters.tsx`: **ОТЛИЧНО**. Реализован полноценный Bottom Sheet (`fixed inset-x-0 bottom-0 rounded-t-3xl max-h-[85vh]`) с ручкой перетаскивания и фиксацией нижней кнопки «Применить фильтры».
   - `SelectionSheet.tsx`: На мобильных экранах подборка открывается как боковая шторка справа (`fixed inset-y-0 right-0 flex max-w-full pl-10`). На узком экране 375px отступ `pl-10` оставляет узкую полоску 40px слева. Согласно п. 3.4 `ux-criteria.md`, на мобильных устройствах шторка подборки должна открываться снизу (Bottom Sheet) либо занимать полный экран (`w-full pl-0`), что значительно комфортнее для управления одной рукой.

3. **Мобильная навигация в шапке:**
   - В `Header.tsx` на смартфонах ссылки «Каталог изделий», «О мастере», «Контакты» скрыты классами `hidden sm:block` / `hidden md:block`. При этом бургер-меню отсутствует. Пользователь на мобильном устройстве не имеет возможности перейти в каталог из шапки сайта.

**Оценка измерения: 6/10 (CHANGES_REQUESTED)**

### 2.4. Измерение 4: Эстетика Luxury Minimalist
*Критерий: Noir & Gold палитра, гармоничная типографика, визуальный «воздух», отсутствие кричащих элементов.*

1. **Цветовая палитра и градиенты:**
   - Фоновые тона: `bg-noir-950` (#09090b / deep graphite noir) создают ощущение приватности и эксклюзивности.
   - Акценты: `text-gold-200`, `text-gold-300`, `bg-gold-500`, деликатные рамки `border-gold-500/20` и `border-noir-800`.
   - Отсутствуют едкие цвета, агрессивные скидочные бейджи («SALE», «СКИДКА -50%») и навязчивая реклама.
2. **Типографика:**
   - Заголовки: благородный `Playfair Display` с умеренным трекингом (`tracking-wide`, `tracking-wider`).
   - Основной текст: удобочитаемый `Inter` с мягким контрастом (`text-noir-300`, `text-noir-400`).
   - Иерархия выдержана: в блоках используется не более трех градаций шрифта.
3. **Пространство и композиция:**
   - Отступы между карточками (`gap-6`, `gap-8`) дают изделиям пространство для восприятия.
   - Изображения украшений имеют пропорцию 1:1 (`aspect-square`) с мягким зумом при наведении (`group-hover:scale-105`).

**Оценка измерения: 9.8/10 (PASSED)**

### 2.5. Измерение 5: Доступность (A11y) и качество взаимодействия
*Критерий: Закрытие по Escape и бэкдропу, удержание фокуса (Focus Trap), явные aria-labels на кнопках-иконках, устойчивость данных.*

1. **Закрытие по клавише Escape и клику на оверлей:**
   - `SelectionSheet.tsx`: ✅ Реализован `window.addEventListener("keydown")` для `Escape` и клик по оверлею (`onClick={closeSelection}`).
   - `CatalogFilters.tsx`: ✅ Реализован `window.addEventListener("keydown")` для `Escape` и клик по оверлею (`onClick={() => setIsMobileOpen(false)}`).
   - ❌ **`InquiryModal.tsx` (CRITICAL DEFECT):**
     - Слушатель клавиши `Escape` **полностью отсутствует**! Нажатие Escape не закрывает окно.
     - Клик по фоновому бэкдропу **не закрывает окно** (`onClick` на затемнении отсутствует, закрыть можно только кнопкой «X»).

2. **Семантика диалоговых окон (ARIA Dialog):**
   - `SelectionSheet.tsx`: `role="dialog" aria-modal="true" aria-label="Моя подборка"`. (PASS)
   - `CatalogFilters.tsx`: `role="dialog" aria-modal="true" aria-label="Фильтры каталога"`. (PASS)
   - ❌ **`InquiryModal.tsx`:** Отсутствуют атрибуты `role="dialog"`, `aria-modal="true"`, `aria-labelledby="inquiry-modal-title"`.

3. **Удержание фокуса (Focus Trap):**
   - Ни в одном из трех модальных окон (`SelectionSheet`, `InquiryModal`, `CatalogFilters` mobile) не реализован `focus-trap`. При навигации клавишей `Tab` фокус может уйти под оверлей на фоновую страницу. Рекомендуется использовать примитивы Radix UI (`@radix-ui/react-dialog`) либо хук захвата фокуса.

4. **Экранные дикторы (Aria-labels):**
   - Кнопки-иконки `X`, `Trash2`, `Minus`, `Plus`, `Search` снабжены информативными `aria-label`.
   - В пагинации корректно проставлен `aria-current="page"` на активной странице.

5. **Сохранность данных и тихая валидация (Data Integrity):**
   - Zustand persist с ключом `marziya-selection-storage` надежно сохраняет состав подборки в `localStorage`.
   - При открытии шторки выполняется тихая валидация (`validateBatch`) без блокирования интерфейса.
   - Недоступные изделия помечаются плашкой «Временно недоступно для запроса» без скрытого удаления. (PASS)

**Оценка измерения: 6.5/10 (CHANGES_REQUESTED)**

### 2.6. Дополнительное критическое замечание: Целостность сценария покупателя (User Journey Flow)

В `ProductCard.tsx` отсутствует ссылка на детальную страницу изделия:
- Ни контейнер изображения, ни заголовок `<h3>{product.name}</h3>` не обернуты в `<Link href={`/product/${product.slug}`}>`.
- Покупатель, находясь в каталоге, не может кликнуть на карточку и перейти к изучению подробных характеристик, минералов, макро-галереи и прямых контактов мастера. Это нарушает базовый клиентский сценарий, описанный в `docs/architecture/product-architecture.md` (раздел 2, Client Journey).

## 4. Конкретные рекомендации и рецепты исправлений (Actionable Tasks)

Для перевода статуса в **APPROVE** фронтенд-команде необходимо выполнить следующие доработки:

### Задача 1. Доработка `InquiryModal.tsx` (DEF-01, DEF-02, DEF-04)
1. **Добавить обработчик Escape и клик по оверлею:**
   ```tsx
   useEffect(() => {
     if (!isInquiryModalOpen) return;
     const onKeyDown = (e: KeyboardEvent) => {
       if (e.key === "Escape") handleClose();
     };
     window.addEventListener("keydown", onKeyDown);
     return () => window.removeEventListener("keydown", onKeyDown);
   }, [isInquiryModalOpen]);
   ```
2. **Сделать бэкдроп кликабельным:**
   Добавить `onClick={handleClose}` на внешний оверлей, а на карточке модалки сохранить `onClick={(e) => e.stopPropagation()}`.
