# ADR-0001: Базовый технологический стек и модель каталога без e-commerce

- **Статус:** `Accepted`
- **Дата:** 2026-09-23
- **Автор:** Lead Architect

## 1. Контекст (Context)
Проект `marziya-gold_ecom` разрабатывается как эксклюзивный сайт-каталог авторских ювелирных изделий мастера. Все изделия изготавливаются исключительно под заказ. Цены динамические и рассчитываются индивидуально. Классическая модель интернет-магазина (складские остатки, корзина с ценами, онлайн-оплата, доставка) не подходит и вредна для позиционирования бренда. 

Ключевое эксплуатационное требование заказчика: **"Под ключ" (Zero-Maintenance)** — продукт должен быть передан клиенту без необходимости дальнейшего технического сопровождения или администрирования серверов разработчиком.

## 2. Принятые решения (Decisions)

1. **Бизнес-модель:**
   - Отказ от цен, корзины, платежных шлюзов и складского учета.
   - Внедрение модели **"Моя подборка"** -> **"Заявка мастеру"** с фиксацией полного JSON-снапшота изделий на момент запроса.
   - Прямые каналы связи ([Telegram], [Позвонить]) на каждой карточке товара.

2. **Frontend-стек:**
   - **Next.js 15+ (App Router)** + **React 19** + **TypeScript** + **TailwindCSS** + **shadcn/ui**.
   - Состояние подборки сохраняется в `localStorage` (Zustand persist) с тихой валидацией доступности товаров.

3. **Backend-стек:**
   - **Java 21 LTS** + **Spring Boot 4.1.1** + **Spring Data JPA** + **Spring Security** + **Flyway**.
   - Авторизация мастера через JWT в `HttpOnly`, `SameSite=Strict`, `Secure` Cookie.
   - Ограничение частоты запросов на создание заявок через `Bucket4j`.

4. **База данных и поиск:**
   - **Managed PostgreSQL 16+**.
   - Динамические характеристики товаров и камней хранятся в **JSONB** в связке с глобальным справочником ключей (`CharacteristicKey`), управляемым мастером.
   - Полнотекстовый и нечеткий поиск реализуется через нативное расширение **`pg_trgm`** с GIN-индексами по названию и артикулу.

5. **Медиафайлы:**
   - Облачный сервис **Cloudinary** (Image CDN). Динамическая нарезка разрешений и конвертация в WebP/AVIF на лету. Никаких файлов на сервере.

6. **Инфраструктура (Zero-Maintenance):**
   - Отказ от самостоятельного Linux VPS.
   - Развертывание на PaaS: **Vercel** (фронтенд) + **Render/Railway** (бэкенд) + **Neon/Supabase** (Managed DB с автобэкапами).

## 3. Последствия (Consequences)
- **Плюсы:**
  - Нулевая необходимость ручного администрирования серверов и продления SSL.
  - Мгновенная загрузка страниц каталога и идеальная индексация в поисковиках.
  - Защита от потери исторической достоверности заявок благодаря JSON-снапшотам.
  - Гибкость в добавлении характеристик ювелирных изделий без правок кода.
- **Минусы / Компромиссы:**
  - Зависимость от облачных сервисов (Vercel, Render, Cloudinary).
  - При переходе на классический e-commerce (с онлайн-оплатой) потребуется существенный рефакторинг.

## 4. Рассмотренные альтернативы (Alternatives Considered)
- *Классический React SPA (Vite):* Отклонен из-за худшего SEO и медленного первого рендера тяжелых страниц каталога.
- *Реляционная модель EAV для характеристик:* Отклонена из-за громоздких SQL-запросов и падения производительности по сравнению с JSONB.
- *ElasticSearch для поиска:* Отклонен из-за избыточной сложности поддержки и затрат на отдельный сервер.
- *Локальный диск сервера для фото:* Отклонен из-за риска переполнения диска и нарушения парадигмы Zero-Maintenance.
